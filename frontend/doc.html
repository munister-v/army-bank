1. Загальний огляд

ARM Bank — мобільний банкінг-застосунок: React PWA (фронтенд) + Flask REST API (бекенд) на Python, з базою даних SQLite/PostgreSQL. Підтримує рахунки, картки, перекази, депозити, кредити, маркетплейс, месенджер, систему оцінки ризику (anti-fraud) та адмін-панель.

Python 3.12 + Flask 3.1 React 19 + TypeScript + Vite 6 SQLite / PostgreSQL Gunicorn + nginx Bearer-токени (secrets.token_urlsafe) bcrypt (12 раундів) WebAuthn / Passkeys Fraud Engine (fuzzy-logic) PWA + Service Worker

2. Архітектура та стек

Шлях запиту від користувача до бази даних:

Браузер (HTTPS)
  → nginx :443 (TLS, rate-limit на /api/auth/*)
    → gunicorn 127.0.0.1:8011 (2 worker-процеси, gthread)
      → Flask app (backend/app.py)
          → Blueprints (routes/*) → Services (services/*) → Repositories (repositories/*)
              → SQLite (database/army_bank.db) / PostgreSQL
      → Статика React PWA (frontend/bank) — SPA fallback на index.html

def hash_password(password: str) -> str:
    """Хешує пароль через bcrypt (або SHA-256 fallback якщо бібліотека недоступна)."""
    if _USE_BCRYPT:
        return bcrypt.hashpw(password.encode(), bcrypt.gensalt(rounds=12)).decode()
    # Fallback: HMAC-SHA256 зі SECRET_KEY (стара поведінка — зворотна сумісність)
    salted = f"{SECRET_KEY}:{password}".encode('utf-8')
    return hashlib.sha256(salted).hexdigest()

def verify_password(password: str, password_hash: str) -> bool:
    """Перевіряє пароль. Підтримує bcrypt ($2b$/$2a$/$2y$) і старий SHA-256."""
    if password_hash.startswith(('$2b$', '$2a$', '$2y$')):
        return bcrypt.checkpw(password.encode(), password_hash.encode())
    ...

def _login_rate_key() -> str:
    # Ключ для rate-limit: окремий лічильник на кожну пару (IP, email)
    data = request.get_json(silent=True) or {}
    identity = (data.get('identity') or '').strip().lower()[:80]
    return f'auth:login:{_auth_client_ip()}:{identity}'

@auth_bp.post('/login')
@rate_limit(AUTH_LOGIN_RATE_LIMIT, AUTH_RATE_WINDOW_SECONDS, key_func=_login_rate_key)
def login():
    try:
        payload = auth_service.login(request.get_json(force=True))
        return jsonify({'ok': True, 'data': payload})
    except Exception as exc:
        # 401, а не 400 — щоб клієнт відрізняв "невірні дані" від "поганий запит"
        return api_error(str(exc), 401)

Маршрут захищений декоратором @rate_limit(...) — ключ враховує IP і email, тож brute-force по одному акаунту або з одної IP блокується окремо.

def transfer(self, user_id, recipient_account_number, amount, description, idempotency_key=None):
    """Виконує переказ через state machine з перевіркою шахрайства."""
    if idempotency_key is None:
        idempotency_key = secrets.token_hex(16)

    # Ідемпотентність: якщо такий запит уже виконано — повертаємо готовий результат
    # (захищає від подвійного списання при повторній відправці форми / ретраї мережі)
    existing = self._payments.get_by_idempotency_key(idempotency_key)
    if existing and existing['status'] == 'completed':
        ...
        return {'account': ..., 'order_id': existing['id'], 'idempotent': True}

    # 1. Валідація: сума > 0, є кошти, рахунки існують, не переказ собі
    if amount <= 0 or amount > 99_999_999.99:
        raise ValueError('Недійсна сума переказу.')
    if float(sender['balance']) < amount:
        raise ValueError('Недостатньо коштів на рахунку.')

                               recipient_account_id=recipient['id'])

    order_id = self._payments.create_order(idempotency_key=idempotency_key, ...,
                                            risk_score=risk.score, risk_level=risk.level,

6. Повна модель даних (SQL-схема)

SQLite: database/schema.sql  ·  PostgreSQL: database/schema_pg.sql. Усі зв'язки — через FOREIGN KEY ... ON DELETE CASCADE (видалення користувача каскадно видаляє його рахунок, картки, операції тощо).

ER-схема

Центральна таблиця PRIMARY KEY FOREIGN KEY → users / accounts Коментар у DDL нижче

Усі зв'язки — через FOREIGN KEY ... ON DELETE CASCADE (видалення користувача каскадно видаляє його рахунок, картки, операції, сесії тощо), окрім audit_logs.user_id — там ON DELETE SET NULL, щоб лог дій зберігався навіть після видалення акаунта.

Повний DDL (SQLite) — з поясненням кожного рядка

Файл цілком: database/schema.sql. Нижче — той самий DDL, але з коментарем -- ... до кожного рядка, що пояснює призначення поля чи обмеження.

PRAGMA foreign_keys = ON;                                    -- SQLite за замовчуванням НЕ перевіряє FK — увімкнути примусово

CREATE TABLE IF NOT EXISTS users (                          -- профіль і облікові дані користувача
    id INTEGER PRIMARY KEY AUTOINCREMENT,             -- унікальний ID користувача (PK)
    full_name TEXT NOT NULL,                       -- ПІБ для відображення в інтерфейсі
    phone TEXT NOT NULL UNIQUE,                    -- телефон; унікальний, може йти для входу/відновлення
    email TEXT NOT NULL UNIQUE,                    -- email — основний логін, унікальний
    password_hash TEXT NOT NULL,                   -- bcrypt-хеш пароля, див. utils/security.py
    role TEXT NOT NULL DEFAULT 'soldier',           -- soldier / admin / platform_admin / operator
    military_status TEXT NOT NULL DEFAULT 'active', -- військовий статус облікового запису
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP, -- дата реєстрації (UTC, ISO-рядок)
    last_seen_at TEXT DEFAULT NULL                  -- оновлюється на кожен запит у auth_required()
);

CREATE TABLE IF NOT EXISTS accounts (                       -- банківський рахунок, рівно 1 на користувача
    id INTEGER PRIMARY KEY AUTOINCREMENT,             -- ID рахунку (PK)
    user_id INTEGER NOT NULL UNIQUE,                -- власник; UNIQUE ⇒ лише 1 рахунок на user
    account_number TEXT NOT NULL UNIQUE,            -- номер рахунку, видається при реєстрації
    currency TEXT NOT NULL DEFAULT 'UAH',            -- валюта рахунку
    balance REAL NOT NULL DEFAULT 0,                 -- баланс; змінюється лише через PaymentCore
    status TEXT NOT NULL DEFAULT 'active',           -- active / frozen
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP, -- дата відкриття рахунку
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE -- видалили user ⇒ видаляється й рахунок
);

CREATE TABLE IF NOT EXISTS sessions (                       -- активні сесії (видані Bearer-токени)
    id INTEGER PRIMARY KEY AUTOINCREMENT,             -- ID сесії (PK)
    user_id INTEGER NOT NULL,                       -- власник токена
    token TEXT NOT NULL UNIQUE,                      -- secrets.token_urlsafe(32) — сам токен
    expires_at TEXT NOT NULL,                       -- термін дії; перевіряє/продовжує auth_required()
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP, -- час видачі токена
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE -- видалили user ⇒ всі його сесії зникають
);

CREATE TABLE IF NOT EXISTS family_contacts (                 -- адресна книга для швидких переказів
    id INTEGER PRIMARY KEY AUTOINCREMENT,             -- ID запису (PK)
    user_id INTEGER NOT NULL,                       -- власник адресної книги
    contact_name TEXT NOT NULL,                     -- ім'я контакту (довільний текст)
    relation_type TEXT NOT NULL,                    -- тип зв'язку: родина / друг / ін.
    phone TEXT,                                       -- телефон контакту (опційно)
    account_number TEXT,                              -- рахунок для швидкого переказу (опційно)
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP, -- дата додавання контакту
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE -- видалили user ⇒ видаляється й книга контактів
);

CREATE TABLE IF NOT EXISTS savings_goals (                  -- особисті цілі накопичення
    id INTEGER PRIMARY KEY AUTOINCREMENT,             -- ID цілі (PK)
    user_id INTEGER NOT NULL,                       -- власник цілі
    title TEXT NOT NULL,                            -- назва цілі ("На авто", "Резерв"...)
    target_amount REAL NOT NULL,                    -- цільова сума
    current_amount REAL NOT NULL DEFAULT 0,          -- скільки вже накопичено
    deadline TEXT,                                    -- бажаний термін досягнення (опційно)
    status TEXT NOT NULL DEFAULT 'active',           -- active / completed / archived
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP, -- дата створення цілі
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE -- видалили user ⇒ видаляються й цілі
);

CREATE TABLE IF NOT EXISTS donations (                      -- історія донатів на фонди
    id INTEGER PRIMARY KEY AUTOINCREMENT,             -- ID запису (PK)
    user_id INTEGER NOT NULL,                       -- хто задонатив
    fund_name TEXT NOT NULL,                        -- назва фонду/збору
    amount REAL NOT NULL,                           -- сума донату
    comment TEXT,                                      -- довільний коментар донора (опційно)
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP, -- дата донату
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE -- видалили user ⇒ видаляється й історія донатів
);

CREATE TABLE IF NOT EXISTS payouts (                        -- нарахування користувачу (зарплата/бонуси/гранти)
    id INTEGER PRIMARY KEY AUTOINCREMENT,             -- ID запису (PK)
    user_id INTEGER NOT NULL,                       -- отримувач нарахування
    title TEXT NOT NULL,                            -- назва нарахування
    amount REAL NOT NULL,                           -- сума нарахування
    payout_type TEXT NOT NULL,                      -- тип: зарплата / бонус / грант / ...
    status TEXT NOT NULL DEFAULT 'credited',          -- credited / pending
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP, -- дата нарахування
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE -- видалили user ⇒ видаляється й історія нарахувань
);

CREATE TABLE IF NOT EXISTS transactions (                   -- журнал усіх операцій по рахунку (книга проводок)
    id INTEGER PRIMARY KEY AUTOINCREMENT,             -- ID операції (PK)
    account_id INTEGER NOT NULL,                    -- рахунок, по якому проведена операція
    tx_type TEXT NOT NULL,                          -- тип: transfer / topup / payment / ...
    direction TEXT NOT NULL,                        -- 'in' (надходження) або 'out' (списання)
    amount REAL NOT NULL,                           -- сума операції (завжди додатна)
    description TEXT NOT NULL,                      -- опис, видимий користувачу
    related_account TEXT,                              -- рахунок контрагента (для переказів)
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP, -- дата/час операції
    FOREIGN KEY(account_id) REFERENCES accounts(id) ON DELETE CASCADE -- видалили рахунок ⇒ видаляється історія
);
-- Кожен переказ створює ДВА рядки: 'out' у відправника + 'in' у отримувача,

    id INTEGER PRIMARY KEY AUTOINCREMENT,             -- ID шаблону (PK)
    user_id INTEGER,                                  -- власник; NULL = системний шаблон (видимий усім)
    name TEXT NOT NULL,                            -- назва шаблону

    amount REAL,                                       -- сума за замовчуванням (опційно)
    description TEXT NOT NULL DEFAULT '',           -- опис платежу за шаблоном
    is_system INTEGER NOT NULL DEFAULT 0,           -- 1 = системний шаблон (для всіх користувачів)
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP, -- дата створення шаблону

CREATE TABLE IF NOT EXISTS push_subscriptions (              -- підписки на web-push сповіщення
    id INTEGER PRIMARY KEY AUTOINCREMENT,             -- ID підписки (PK)

CREATE TABLE IF NOT EXISTS cards (                         -- картки (virtual/фізичні), прив'язані до рахунку

Усі бізнес-маршрути доступні під префіксом /api/* і повертають JSON. Авторизація — заголовок Authorization: Bearer <token>. Повна специфікація: /api/docs (OpenAPI/Swagger), JSON-схема — /api/openapi.json, генератор — backend/api_docs.py.

8. Безпека

  • Паролі — лише bcrypt-хеші (12 раундів), у відкритому вигляді не зберігаються. utils/security.py
  • Токени сесій — криптографічно випадкові (secrets.token_urlsafe(32)), з TTL та автопродовженням.
  • Passkeys / WebAuthn — підтримка безпарольного входу (Face ID тощо). routes/passkey_routes.py
  • Anti-fraud скоринг — кожен переказ проходить fuzzy-logic оцінку ризику. services/fraud_engine.py
  • HTTPS обов'язково — HTTP редіректить на HTTPS, HSTS-заголовок.
  • Rate limiting — декоратор @rate_limit(...) на /api/auth/* (бекенд) + nginx обмеження 5 req/s з IP. routes/helpers.py
  • CORS — лише білий список дозволених доменів (munister.com.ua, bank.munister.com.ua тощо). app.py
  • HTTP-заголовки — X-Content-Type-Options, X-Frame-Options (для API), Referrer-Policy, Permissions-Policy.
  • Cache-Control: no-store для всіх /api/* — конфіденційні дані не кешуються.
  • Аудит — таблиця audit_logs фіксує значущі дії користувачів/адмінів.
  • Ідемпотентність платежів — заголовок Idempotency-Key запобігає повторному виконанню операції. services/payment_core.py
  • Месенджер — шифрування повідомлень у спокої (Fernet, ротація ключів). services/messenger_crypto.py
  • Секрети — у файлі .env на сервері (права 600), не потрапляють у git.
  • Firewall — на сервері відкриті лише 22 (SSH), 80/443 (HTTP/HTTPS).
  • Gunicorn слухає лише 127.0.0.1:8011 — недосяжний напряму з інтернету.
